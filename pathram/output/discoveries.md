## I and you are apeksha markers, not entity names. I=vacaka=chala-apeksha (speaker, moving frame). you=addressee=sthira-apeksha (graph/nam, fixed frame). When utterance crosses the boundary, pronouns invert. Every question is implicitly apeksha-nam; sambodhana makes it explicit.

## Greeting words (hello, hi, hey) are not nodes — they are shabda signals on sangati roots, like common-sense-events maps verbs to kshaya/vriddhi. english-grammar-signals.shabda maps: hello→sambodhana, hey→abhisambodhana, greetings→aamantrana. Detection: shabda lookup, not node walk.

## Sambodhana is not a special mode — the graph already acknowledges every utterance through panchaavayava (five limbs). Sambodhana is the case where only pratijna exists — the speaker is present, nothing is sought. The triple [hello, sambodhana, hello] enters the graph like any other signal.

## Vaisheshika padarthas formalized as sangati/padartha/: padartha (category), dravya (substance), guna (quality), karma (action), samanya (universal), vishesa (particular), samavaya (inherence), abhava (absence), amsha (part). thing=padartha, some=amsha, something=amsha+padartha. karma and abhava moved from parampara/ and mula/ respectively.

## Sambodhana has three degrees (amshas): sambodhana (neutral — hello, hi), abhisambodhana (emphatic — hey, yo), aamantrana (formal — greetings). Created as sangati nodes under grammar/vibhakti/. The degree is carried by the shabda signal, not by separate bhasha nodes.

## Pipeline timing is Datalog stratified evaluation with monotone fixpoint. Three mechanisms: (1) Monotone enrichment — signals only added, never removed. Each tantra emits alongside originals, never consumes. Graph only grows within a stratum. (2) Fixpoint iteration — avrti-refine runs until no new triples appear. A signal emitted late in pass N is visible to early steps in pass N+1. This handles within-layer async. (3) Layer ordering (construct → assert → refine → expand → detect → dispatch → emit) handles cross-layer dependencies. Each layer's output is frozen input to the next. Within refine, the krama chain orders sub-steps: sandhi-kosha → ... → sankhya-bandha → swarupa-anuvada. swarupa-anuvada MUST be after sankhya-bandha (needs sankhya edges to propagate). The constraint: every sub-tantra must be monotone (only add triples). sankhya-bandha was non-monotone (consumed asprista-sankhya) — fixed to emit alongside instead. True monotonicity means the graph is append-only within a stratum, guaranteeing fixpoint convergence.

## Information theory connection to pipeline formalized. The graph already has nodes for the full Shannon model: transducer (emit-triples), encoding/decoding (word↔triple conversion), channel (question graph), noise (mithya), redundancy (monotonicity), capacity (fixpoint saturation), mutual-information (shared structure word↔concept). Pipeline layers map to info theory: construct=encoding, refine=error-correction (monotone enrichment removes ambiguity), detect=decoding (extracts intent signals), dispatch=decoding (selects strategy from channel), emit=re-encoding (graph→natural language). The monotonicity constraint = no information loss in the channel. The fixpoint = channel capacity (iterate until saturated). assertion-bandha = redundancy extraction (IS-A encoded redundantly in sentence, extracted to single swarupa edge). sankhya-bandha = signal binding (floating number is noise, binding to concept converts noise to signal, reduces entropy). swarupa-anuvada = error correction via redundancy (swarupa edge is structural redundancy, propagation fills in missing signals).

## Signal bus architecture: detect-signals and dispatch-answer now communicate through named graph edges instead of a positional list. detect-X tantras (detect-viveka, detect-anumana, detect-count) each return signal pairs [[name, value], ...]. detect-signals merges all pairs and writes them to the graph via write-signals as [_signal, name, value] triples. dispatch-answer reads them via read-signal. The contract is symmetric: write-signal/read-signal are inverses. Adding a new dispatch mode requires only: (1) write a detect-X tantra returning signal pairs, (2) add read-signal calls in dispatch-answer. No positional coupling, no index tracking. This mirrors the encoding/decoding duality from information theory — detect encodes intent into the channel, dispatch decodes it.

## Scan→relational migration insight: scan was a flatmap (rewrite graph in-place), not an append operation. Replacing scan with append-triples broke ordering assumptions that downstream consumers depended on. The fix was two-part: (1) make consumers relational — join through ownership edges instead of positional scanning, (2) make producers grade-scoped — sequential reduce within each sentence (small, bounded), relational queries across sentences. Grade = fact set. The graded ring structure IS the Datalog stratification boundary.
